## 1. What it is, and how it differs from WEBSTART

> *"WEBSTART builds the product correctly. WEBSTART X challenges the completed
> product against best-in-class experiences and elevates it. They are separate
> workflows and may be used independently."*

WEBSTART repaired an unfinished project. WEBSTART X assumes a finished one and
asks whether it is *good enough compared to the best*, which is a different
question and a harder one. It begins only from a launch-ready or launched
state — which this project reached today.

**Activation is explicit: the code word `WEBSTART X`.** Until the owner says
it, this document is reference material. Starting a redesign because a redesign
framework arrived would be the same failure the original protocol warned about
— treating the existence of a phase as a reason to execute it.

## 2. The eleven stages

| | Stage | What it produces |

| X03 | Experience Deconstruction | Why each reference works, and what is transferable |
| X04 | Reference-Driven Redesign | Preserve / borrow-as-principle / adapt / improve / reject |
| X05 | Redesign Direction | Current → Desired → Why → What changes → What stays |
| X06 | High-Impact Experience Upgrade | Navigation, hero, hierarchy, conversion, trust, density |
| X07 | Interaction & Motion | Motion only where it aids comprehension or feedback |
| X08 | Mobile Excellence | Mobile re-designed, not compressed |
| X09 | Design System Refinement | Type, spacing, grid, components, states, motion tokens |
| X10 | Validation & Comparative Review | Redesign vs baseline vs references |
| X11 | World-Class Gate | Meaningful improvement, or it is not complete |

## 3. The guardrails, and where this project already sits against them

| Guardrail | Standing here |
| --- | --- |
| **Brand preservation** | Logo, palette, type and voice are settled and applied consistently (Phase 09) |
| **Content preservation** | Every string is bilingual and generated from data files; rewriting is visible in a diff |
| **Business preservation** | Prices, packages and the WhatsApp conversion path are business data, not design material |
| **No blind copying** | Same rule as the original protocol. Phase 02 benchmarked nine competitors without copying one |
| **Evidence before change** | The project already refuses changes without a stated reason — `docs/30` is eleven of them |
| **Keep good work** | The audit's whole premise. Nothing was rebuilt for its own sake |
| **Progressive improvement** | High-impact first, decorative churn last |

Nothing in the guardrails conflicts with what has been built. That is worth
saying plainly, because it means WEBSTART X here would be **refinement, not
reversal**.

## 4. Two honest constraints before it is activated

**X02 and X03 need reference websites, and this environment cannot fetch
them.** The egress policy blocks outbound page requests — the same limitation
that left Phase 02 partial, where nine competitors were benchmarked from
knowledge rather than from their live pages. A benchmark of experiences that
nobody in the room has opened is a weak benchmark. The fix is cheap: the owner
names the references and supplies screenshots or recordings, and the analysis
runs on what is actually in front of us.

**X01 overlaps with work that already exists.** `docs/27` is a current-state
audit with a KEEP / IMPROVE / REBUILD / REMOVE / ADD map, re-checked against
the repository today. X01 should extend it — visual hierarchy, page rhythm,
motion, service discovery, the things a *quality* audit asks that a *completeness*
audit does not — rather than start a second one that will drift from the first.

## 5. What this project would most likely gain from it

Recorded now, before any benchmarking, so it can be compared against what the
references actually say:

- **The homepage is nine sections long.** It was built to be complete. Whether
  it is *paced* — whether a buyer reaches the price before fatigue — is exactly
  an X06 question, and no phase has asked it.
- **Motion is guarded but sparse.** 23 `prefers-reduced-motion` guards protect
  what exists; X07 asks whether motion is doing enough work at all.
- **Mobile is verified, not designed.** Phase 13 proves nothing overflows and
  every target clears 44px. X08 asks a different question: is the phone
  experience *designed for a phone*, or a correct compression of the desktop?
- **Proof is thin, and it is a design problem as much as a content one.** One
  case study, no homepage proof strip. X06 would put trust signals where a
  buyer looks rather than where there was room.
